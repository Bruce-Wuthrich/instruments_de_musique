# Ajout de l'image Docker PHP 8.4

- **Date** : 2026-11-09 12:10
- **Branche** : feature/01-install-claude

## Fichiers modifiés ou créés

- `docker/php/Dockerfile` — créé : `php:8.4-apache` + extensions `intl`, `pdo_mysql`, `zip`, `opcache`, `git`/`unzip`, Composer 2, `mod_rewrite` ; `www-data` reprend l'UID/GID 1000 de l'utilisateur WSL.
- `docker/php/vhost.conf` — créé : Apache sert `public/`, toutes les URL renvoyées vers `index.php` (`FallbackResource`).
- `docker/php/php.ini` — créé : fuseau `Europe/Brussels`, `memory_limit` 512M, uploads 20M (photos / extraits sonores).
- `compose.yaml` — modifié : service `php` (build du Dockerfile, projet monté dans `/var/www/html`, `DATABASE_URL` pointant vers l'hôte `database`, démarre après MariaDB).
- `compose.override.yaml` — modifié : `php` exposé sur http://localhost:8000 avec `MAILER_DSN=smtp://mailer:1025` ; interface Mailpit fixée sur le port 8025.
- `.dockerignore` — créé : exclut `.git`, `var`, `vendor`, `public/assets` du contexte de build.
- `CLAUDE.md` — modifié : section Commandes adaptée à Docker, description des services.

## Raisons

L'environnement Docker ne contenait pas de PHP : le projet doit tourner en PHP 8.4 dans Docker, comme la base et Mailpit.

## Agents utilisés

- Aucun (Claude Code seul).

## Points d'attention / suite

- Non testé : Docker Desktop n'était pas lancé. Pour vérifier :
  ```bash
  docker compose up -d --build
  docker compose exec php php -v            # PHP 8.4.x
  docker compose exec php composer install
  ```
  puis ouvrir http://localhost:8000.
- Pas de worker Messenger dans Docker : lancer `php bin/console messenger:consume async` dans le conteneur pour envoyer les mails.
- Si l'UID WSL n'est pas 1000 : `docker compose build --build-arg UID=$(id -u) --build-arg GID=$(id -g) php`.
